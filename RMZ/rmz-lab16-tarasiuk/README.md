# Лабораторна робота 16 — ffmpeg і вимірювання

## Запуск

Потрібні Python 3, FFmpeg/ffprobe, NumPy, Pillow, Matplotlib, ReportLab. Встановіть пакети командою `python3 -m pip install numpy pillow matplotlib reportlab imageio-ffmpeg`, переконайтеся, що `ffprobe` доступний у PATH, і виконайте `python3 lab16.py`. Якщо системного ffmpeg немає, скрипт використовує бінарник із `imageio-ffmpeg`. Графіки, JSON і звіт PDF з'являються в `results/`; тимчасові відео — у `work/`.

Відтворюваний тестовий кліп генерується скриптом: 640×352, 30 fps, 5 секунд, FFV1 у Matroska, без втрат. `probe()` читає контейнер, кодек, розмір, fps, формат пікселів, бітрейт і тривалість. `encode()` повертає шлях, час та байти; `measure()` вирівнює PTS, формат пікселів і діапазон та парсить PSNR/SSIM зі stderr FFmpeg.

## Невирівняне порівняння та кодеки

Скрипт окремо запускає навмисно неправильне PSNR-вимірювання без нормалізації й зберігає stderr у `unaligned_stderr.txt`. Для цієї версії FFmpeg різниця між CRF 18 і 40 мала: 27.77 проти 27.46 дБ; у stderr присутні попередження про несумісні timebase і некоректні DTS. Такі результати не слід використовувати для вибору якості.

Також виміряно H.264 (CRF 18/23/28), H.265 (20/25/30) та AV1 (25/35/45). На цьому кліпі всі значення PSNR близькі до 24.5 дБ, тож ціль 39.5 дБ не потрапляє в інтервал жодної кривої. Скрипт не екстраполює розмір за межі вимірів; відповідні значення лишаються `null` у JSON. `codec_comparison.png` показує виміряні точки. Один панорамний фрагмент — обмежена база для загальних висновків про кодеки.

## Відповіді

1. Контейнер є обгорткою доріжок і метаданих; кодек стискає аудіо або відео. MP4 може зберігати відео H.264 чи H.265.
2. CRF задає цільову якість зі змінним бітрейтом; `-b:v` орієнтує кодування на бітрейт, а якість залежить від складності сцени.
3. Шкала CRF залежить від кодека; однаковий CRF між кодеками не означає однакову якість. Порівнювати потрібно за спільною метрикою.
4. PSNR вимірює середню піксельну помилку відносно еталона в децибелах; він не повністю відповідає людському сприйняттю.
5. Перед PSNR/SSIM кадри треба вирівняти за часом, форматом пікселів і діапазоном значень.
6. Майже незмінний результат при зміні CRF або нереалістичні значення можуть означати помилку зіставлення, timebase чи діапазону; перевіряю попередження і параметри обох потоків.
7. Для цього тестового кліпу обираю CRF 23 через невеликий розмір і найкращий компроміс SSIM; якість підтверджую переглядом і вимірами на цільовому відео.
