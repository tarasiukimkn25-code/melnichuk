# Лабораторна робота 15 — компенсація руху

## Запуск

Python 3, NumPy, Pillow, Matplotlib і FFmpeg. `python3 -m pip install numpy pillow matplotlib imageio-ffmpeg` та `python3 lab15.py`. Скрипт перевіряє пошук блоків, генерує векторні поля, різницю кадрів і JSON у `results/`.

Алгоритм використовує блок 16×16, повний пошук у вікні ±16 пікселів і SAD як суму модулів різниць. Функція `search_block` повертає `(dy, dx, SAD)`, а `compensate` — кадр-прогноз, вектори `(bx, by, dx, dy)`, SAD без компенсації та після неї. Межі перевіряються з усіх боків; неповні граничні блоки копіюються без змін.

## Перевірки та експерименти

Вісім контрольних перевірок завершилися `OK`, зокрема нульовий зсув для нерухомого блоку, правильний напрямок панорами, межі, формат прогнозу й зменшення SAD. Для однакового згенерованого панорамного фрагмента (зсув 6 px) SAD зменшився з 10.90M до 0.22M, тобто у 50.1 раза; ентропія залишку — з 7.85 до 0.32 біт/піксель.

| Сцена | SAD до → після | Виграш | Ентропія до → після |
|---|---:|---:|---:|
| Нерухома камера | 0.14M → 0.14M | 1.0× | 1.57 → 1.57 |
| Рівна панорама | 10.90M → 0.22M | 50.1× | 7.85 → 0.32 |
| Тремтлива камера | 10.83M → 0.77M | 14.1× | 7.83 → 1.03 |
| Незалежний рух об'єктів | 1.42M → 0.49M | 2.9× | 0.52 → 0.24 |

Набори кадрів синтетичні, бо у відкритих вкладеннях не було доступного вихідного відео/генератора. На згенерованому демонстраційному ролику скрипт також зберігає два вибрані сусідні кадри, вектори й показники (`--video шлях/до/відео.mp4` приймає власне відео). У поточній синтетичній сцені без руху немає компенсаційного виграшу; у сцені з незалежним рухом залишок залежить від меж блоків та локального збігу.

## Відповіді

1. Вектор руху задає зсув блока поточного кадру до найкращого блока попереднього кадру. Для кадру 640×352 з блоком 16×16 маємо 40×22 = 880 блоків/векторів.
2. SAD обчислюється простими відніманням, модулем і додаванням; квадрат потребує дорожчої операції та сильніше зважує великі похибки.
3. Для вікна ±16 є 33×33 = 1089 кандидатів на блок; повний пошук простий, але дорогий.
4. Панорама має майже однаковий зсув для багатьох блоків, тому попередній кадр добре прогнозує поточний. Статична сцена і так має майже нульову різницю.
5. Якщо розмір не кратний 16, неповна крайова смуга не покривається повним блоком; реалізація залишає її як у поточному кадрі.
6. Незалежний рух створює різні вектори сусідніх блоків і шви на їх межах; через це ентропія залишку може зрости.
7. Компенсація руху не стискає без втрат сама по собі: кодек передає вектори та залишок. Малий залишок зазвичай кодується дешевше.
